# Programs

План реализации раздела «Тренировки» (программы тренировок: список, детальная страница, редактор). Составлен по итогам исследования бэкенда/фронтенда и схемы БД (`docs/DB.md`, миграции 00004–00005). Схема БД уже готова — новые миграции не требуются.

## Терминология

В идее раздел «тренировки» соответствует сущности **программа** из схемы БД. Проведение тренировок (журнал выполнения) — отдельная сущность `workouts`, в первую итерацию не входит.

| Понятие раздела | В схеме БД |
|---|---|
| Тренировка, созданная админом (Gym) | `programs` с `owner_id IS NULL` (готовая, `is_published`) |
| Своя тренировка пользователя | `programs` с `owner_id` = пользователь (личная) |
| «В какой день какие упражнения, повторы, вес» | `program_days` → `program_exercises` → `program_sets` (каждый подход отдельно — можно задать пирамиду 12×40 → 10×45 → 8×50) |
| Активные тренировки пользователя | `user_programs` (`is_active`) — **не входит в итерацию 1** |
| Проведение тренировки (отметки подходов) | `workouts` → `workout_exercises` → `workout_sets` (план `planned_*` копируется при старте) — **не входит в итерацию 1** |
| Календарь / ближайшая тренировка | `program_schedule_rules` / `user_schedule_rules` — **не входит в итерацию 1** |

Готовые ограничения схемы:

- Права по создателю: личную программу правит владелец, готовую — только админ (`middleware.Admin()` написан, к роутам не подключён).
- Одна незавершённая тренировка на пользователя — UNIQUE по виртуальной колонке `active_user_id` в `workouts` (актуально для будущих итераций).
- `copied_from_id` — основа для «Копировать себе» из готовой программы.

**Терминология в UI:** во всех пользовательских текстах фронтенда сущность называется **«тренировка»** (не «программа»): «Создать тренировку», «Мои тренировки», «Тренировки Gym», «Новая тренировка», «Удалить тренировку?» и т.д. Кодовые идентификаторы (`stores/programs.js`, `ProgramCard`, роуты `program-*`, namespace i18n `programs`) остаются выровнены с бэкенд-сущностью `programs`.

## Решения по продукту (согласованы)

1. **Активные сверху** — только программы, по которым пользователь занимается (`user_programs.is_active`); в итерации 1 блока не будет, появится вместе с подпиской на программу и календарём.
2. **Подписка на программу** — явная (`user_programs`): в будущем активация программы задаёт расписание → календарь показывает ближайшую тренировку → на главной секция «ближайшая тренировка» (дата, время, название, группы мышц) с кнопкой старта. Сначала — настройка и создание самих тренировок.
3. **Готовую программу нельзя редактировать** обычному пользователю — вместо этого кнопка **«Копировать себе»** (личная копия с `copied_from_id`), дальше он правит свою копию.
4. **Объём итерации 1** — список + детальная страница + редактор (создание/изменение/копирование). Без `user_programs`, без проведения тренировок, без календаря.
5. **Пустые дни разрешены** — в UI заглушка «нет упражнений», валидацию в API не делаем.
6. **Обновление программы** — полная замена структуры (дни/упражнения/подходы) одним `PUT`-запросом, в одной транзакции.

## API (контракты)

Группа `/api/v1/programs`, все эндпоинты за `middleware.Auth`; доступ к готовым программам на изменение — по роли `admin` (проверка в сервисе/хендлере, `owner_id IS NULL`).

| Метод, путь | Доступ | Назначение |
|---|---|---|
| `GET /programs` | auth | Список: готовые (`is_published=1`, у админа + черновики) + свои личные. Query: `q`, `level`, `mine`, `page`, `per_page` |
| `GET /programs/:id` | auth | Детальная: программа + дни (по `position`) + упражнения дня (имя, `tracking_type`, медиа каталога по `Accept-Language`) + подходы. Готовая опубликованная — всем; личная — владельцу; админ — всё (включая черновики) |
| `POST /programs` | auth | Создание. Обычный пользователь — всегда личная; админ может пометить как готовую (`is_published`, `owner_id IS NULL`) |
| `PUT /programs/:id` | owner / admin | Полное обновление (шапка + структура дней) в одной транзакции |
| `DELETE /programs/:id` | owner / admin | Удаление личной — владелец, готовой — админ |
| `POST /programs/:id/copy` | auth | Копировать готовую себе: `owner_id` = текущий пользователь, `copied_from_id` = `:id`. Личную копирует владелец себе же (дубликат) |

### Формат body для `POST` и `PUT` (единый)

```json
{
  "name": "Моя программа",
  "description": "…",
  "level": "intermediate",
  "is_published": false,
  "days": [
    {
      "name": "День A: грудь и трицепс",
      "exercises": [
        {
          "exercise_id": 42,
          "rest_after_sec": 60,
          "sets": [
            { "set_number": 1, "reps": 12, "weight_kg": 40, "rest_sec": 90 },
            { "set_number": 2, "reps": 10, "weight_kg": 45, "rest_sec": 90 }
          ]
        }
      ]
    }
  ]
}
```

- Поля подхода `reps` / `weight_kg` / `duration_sec` / `distance_m` — опциональны; набор определяет `tracking_type` упражнения каталога.
- `PUT`-реализация: удалить старые `program_days` (каскадом уйдут упражнения/подходы) → вставить новые, всё в одной транзакции.
- Уникальность `set_number` в пределах упражнения обеспечит схемой (существующий UNIQUE).

## Этап 5. Фронтенд: редактор (`ProgramEditorView.vue`, роуты `/workouts/new` и `/workouts/:id/edit`, вне меню)

- Шапка: имя, описание, level; для админа — переключатель «Готовая программа» (`is_published`).
- Дни: добавить / удалить / переименовать / поменять порядок.
- В дне: добавить упражнения через поиск по каталогу (переиспользование компонентов `components/exercises`), удалить, порядок, отдых после упражнения.
- У упражнения: список подходов — добавить/удалить строку, поля по `tracking_type`, `set_number` автоматически, отдых после подхода.
- Сохранение: `POST` (создание) или `PUT` (полная замена). При редактировании — загрузка текущей структуры в форму.
- Редактирование готовой админом = та же страница; редактирование готовой обычным пользователем недоступно (только копия).
